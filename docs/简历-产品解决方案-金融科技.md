## 项目经验

### 贷后风险智能运营平台（RIS OS）— 产品负责人 & 全栈实现

*2026.03 – 2026.04 | 个人项目 | 对标重庆农商行 JT2020143 招标交付标准*

**一句话概述**：为商业银行小微企业贷后预警场景，从零设计并工程实现了一套覆盖"监控→预警→核查→策略迭代"完整闭环的风险运营平台原型，交付物覆盖银行招标文件要求的全部 10 项核心产出。

**业务设计能力体现**：

- **角色化工作台设计**：拆解银行贷后业务三条核心岗位——
  - 客户经理（张明/RM001）：关注预警发现→认领核查→处置闭环，首页直接展示名下高风险企业 KPI 与待处置队列
  - 风控建模师（张三）：关注特征工程→模型实验→版本管理→决策流部署，首页展示在跑实验与 PSI 漂移
  - 策略审批员（王五）：关注回溯验证→Diff 审查→发布审批→效果追踪，首页展示待审批变更与策略命中率
- **业务流程闭环**：从企查查实时预警数据入池 → 客户经理认领核查 → 关联欺诈模式库与规则库 → 风控建模师调优模型 → 策略审批员发布变更 → 效果回溯验证，形成完整叙事逻辑
- **招标交付物映射**：10 项核心交付物（预警规则、流程设计、数据集市、处置流程、策略报告、模型报告、IT 需求书、改造需求书、监控方案、迭代方案）均在平台中有对应模块

**工程能力体现**：

- **前端架构**：React 18 + TypeScript + Vite 6 + Ant Design 5 + Tailwind CSS v4，54 个页面，模块化路由 + 懒加载
- **状态管理**：Zustand 5.0 + persist 中间件实现 localStorage 持久化，角色切换实时联动导航栏/首页/DemoFlowNav
- **Mock 工程化**：MSW (Mock Service Worker) 2.x 浏览器端拦截 fetch，56 个页面零代码改动即可在后端离线时完整演示；18 个散落的 mock 文件统一收敛为单一数据源，测试与运行时共享
- **后端**：FastAPI + Python 3 + SQLite，RESTful API 设计（/api/scenario/post-loan/*）
- **工程规范**：TypeScript strict 模式零错误，组件文件 <400 行，完整的 DemoFlowNav 角色分流设计

**产品方法论体现**：

- 定义了 FP（欺诈模式）/ RC（规则调优案例）双向引用体系，确保 mock 数据满足业务叙事一致性（例如"FP-01 资金挪用 → RC-05 司法权重调优 → 策略包 V2.5.0"可完整追溯）
- 设计了"黄金测试用例"：张明在首页发现预警 → 进入预警大盘 → 认领核查 → 查看欺诈模式库 → 张三在模型工厂调优 → 王五在发布审批通过 → 回溯验证效果，全链路可演示
- 采用渐进式演示设计：默认启用 MSW mock（无需后端），设置环境变量切回真实 API

**技术栈**：React 18 · TypeScript · Vite 6 · Ant Design 5 · Tailwind CSS v4 · Zustand · MSW 2.x · FastAPI · Python 3 · SQLite
