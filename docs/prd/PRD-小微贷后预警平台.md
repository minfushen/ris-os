# 产品需求文档（PRD）—— 头部农商行小微企业贷后预警平台

> **文档定位**：本 PRD 是《项目实施计划书-小微贷后预警》（JT-DEMO-001）的产品化翻译。所有业务口径、指标、范围均以计划书为唯一事实来源。
> **客户口径**：本项目为脱敏演示案例，客户名统一以"头部农商行"指代，项目编号为演示编号。
> **开源借鉴**：本 PRD 融合了 ant-design-pro（企业级中后台工程规范）、finance-risk-rag（金融风控 RAG 架构）、DolphinScheduler（工作流编排与版本治理）的实现思路，用于指导技术选型与模块划分。

---

## 1. 项目背景与目标

### 1.1 业务痛点（为什么做）

| 痛点 | 现状 | 后果 |
|------|------|------|
| 贷后风险识别被动 | 人工抽检 + 静态规则 | 风险暴露平均滞后 15 天，发现时损失已发生 |
| 数据源分散 | 客户/贷款/还款/资产负债/交易/征信/工商/司法/税务散在各系统 | 无统一风险数据集市，特征口径不一致 |
| 坏样本稀缺 | 小微逾期率偏低（部分产品 <1%） | 坏样本不足导致建模难 |
| 产品差异大 | 担保类/政策性/信用类客群风险表现差异显著 | 需差异化建模，一模型通用不可行 |
| 可落地性要求高 | 模型要部署到决策引擎、与新信贷系统集成 | 工程化与知识转移要求高 |

### 1.2 核心目标（做成什么样）

| # | 目标 | 衡量指标 |
|---|------|---------|
| 1 | 贷后预警体系搭建 | 覆盖工作架构、风险策略、预警模型、监控体系、处置流程 |
| 2 | 客户/资产风险评估 | 贷后风险评分模型量化违约概率 |
| 3 | 数据体系与风险数据集市 | 整合 8 大变量域、近千维特征 |
| 4 | 模型部署上线 | 部署到决策引擎，过 SIT/UAT/生产测试/批量验证 |
| 5 | 知识转移 | 行方具备自主优化能力 |
| 6 | （扩展）客户 LTV 量化评估 | 贷前额度授信/贷中营销预警/贷后挽留催收三场景 |

### 1.3 关键效果指标

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 预警时效 | 15 天 | 5–7 天 |
| 人工排查工作量 | — | 降低 30%–40% |
| 覆盖范围 | — | 前六大小微产品（余额 88%、客户 96.75%） |

## 2. 项目范围

### 2.1 范围内（In Scope）

- 8 大变量域数据体系与风险指标集市建设（客户/贷款/还款/信用卡/资产负债/交易/征信/三方）
- 逻辑回归 + WOE 评分卡建模（变量筛选 IV/VIF/逐步回归、WOE 分箱、模型验证 PSI/KS/GINI、校准）
- 贷后预警策略与模型部署到决策引擎、与新信贷系统集成
- 监控体系（特征缺失率/分布/PSI）与处置闭环
- LTV 量化评估扩展（分类+回归双模型、LTV×风险/LTV×营销矩阵）
- 知识转移（文档、代码、培训）

### 2.2 范围外（Out of Scope）

- 决策引擎本身的建设（用行方既有引擎，我方是集成方不替换）
- 担保圈/关联图谱自建（如落地靠行内厂商接口调用）
- 贷前审批放款决策（模型只做预警与辅助，不替代授信决策）
- 核心交易系统改造

## 3. 用户画像与角色

> 对齐实施计划书"资源与组织"章节，平台面向三类核心用户。

### 3.1 P1 - 客户经理（RM，贷后主管/客户经理）

```
角色：张明 / 王芳 / 李华
职责：预警发现、认领核查、处置闭环、催收作业
使用频率：每日
核心场景：打开平台看今日预警 → 查看风险画像 → 核查处置 → 归档
```

**核心诉求**：
- 3 秒内看到"今天有多少预警要处理"
- 预警详情一键查看，风险画像一目了然
- 核查 → 处置整个流程在一个界面完成
- 处置完成后系统自动归档

### 3.2 P2 - 风控建模师（Risk Modeler）

```
角色：模型/算法工程师
职责：特征工程、模型实验、决策流编排、模型验证
使用频率：每周
核心场景：样本圈选 → 特征筛选 → WOE 分箱 → 评分卡训练 → KS/GINI/PSI 验证 → 部署
```

**核心诉求**：
- 特征工程可视化，不用每次都写 SQL
- 模型实验管理（Champion / Challenger 版本对比）
- 决策流编排可拖拽，不写代码
- 仿真回溯结果可追溯、可复现

### 3.3 P3 - 策略审批员（Strategy Approver）

```
角色：风险管理部策略审批官
职责：策略变更 Diff 审查、回溯验证、发布审批
使用频率：每月
核心场景：查看策略 Diff → 回溯验证结果 → 影响面评估 → 审批/退回/驳回
```

**核心诉求**：
- 策略变更 Diff 清晰可见
- 回溯验证结果一目了然
- 审批流程标准化，留记录

## 6. 关键业务流程

### 6.1 预警处置闭环（客户经理视角）

```
预警触发 → 预警大盘/探照灯 → 认领核查 → 风险画像查看 → 处置决策 → 处置执行 → 归档 → 复盘质检
                ↑                                              ↓
         监控名单批量导入 ← 额度预检/风险评估 ← CSV 上传
```

### 6.2 模型开发上线流程（风控建模师视角）

```
样本圈选 → 好坏定义（滚动率分析）→ 特征工程（8 大变量域）→ 变量筛选（IV/VIF/逐步回归）
    → WOE 分箱 → 评分卡训练 → 验证（KS/GINI/PSI）→ 校准 → 模型评审（M2 里程碑）
    → 部署决策引擎 → SIT/UAT/生产测试 → 上线 → 监控（PSI/KS 衰减）→ 迭代优化
```

### 6.3 策略发布审批流程（策略审批员视角）

```
策略变更 → 规则 Diff → 仿真回溯（历史数据回放）→ 影响面评估 → 审批（通过/退回/驳回）
    → 灰度发布 → 一键回滚（异常时）→ 监控生效
```

## 7. 数据体系设计

### 7.1 8 大变量域（对齐计划书）

| 变量域 | 数据源示例 | 刷新频率 | 典型变量 |
|--------|-----------|---------|---------|
| 客户信息域 | ECIF 客户主档 | 实时 | 客户类型、行业分类、成立年限 |
| 贷款业务域 | 新信贷系统借据 | 实时 | 贷款余额、期限、利率、担保方式 |
| 还款流水域 | 核心还款流水 | 实时 | 还款金额、还款时间、逾期天数 |
| 信用卡域 | 信用卡账单与额度 | T+1 | 额度使用率、最低还款额、账单金额 |
| 资产负债域 | 存贷汇与理财余额 | T+1 | 存款余额、理财持仓、资产负债比 |
| 交易行为域 | 对公交易流水（972 行变量清单） | 实时 | 交易频率、交易对手、资金流向 |
| 征信域 | 人行征信与多头借贷 | 月更 | 多头查询次数、对外担保、历史逾期 |
| 三方数据域 | 工商/司法/税务/企查查 | T+1 | 被执行/限高、纳税信用、经营异常 |

### 7.2 评分卡建模方法论

| 环节 | 方法 | 说明 |
|------|------|------|
| 好坏定义 | 滚动率分析 | 2 期逾期扩展为两次 1 期，不固定表现窗口 |
| 样本处理 | SMOTE 过采样 | 坏样本稀缺（逾期率 <1%）时的扩充策略 |
| 变量筛选 | IV / VIF / 逐步回归 | 从近千维特征中筛选入模变量 |
| 分箱 | WOE 分箱 | 缺失值按业务含义灵活分箱 |
| 模型 | 逻辑回归评分卡 | 可解释优先，监管友好 |
| 验证 | KS / GINI / PSI | 区分能力与稳定性双验证 |
| 校准 | 基准分 600=好坏比 20:1 | 每翻倍 +20 分 |

|------|------|---------|
| 坏样本稀缺 | 高 | 滚动率分析定好坏、SMOTE 过采样、不固定表现窗口、全部坏样本建模+好样本 40:1 抽样验证 |
| 特征线上线下不一致 | 高 | 字段映射表（定义/来源/频率/逻辑/责任部门写死）+ 上线前历史回放比对 + 上线后 PSI 监控 |
| 业务不敢改策略/上线 | 高 | 上线流程"开发→测试→历史回放→灰度→监控→生效"+ 一键回滚 |
| 产品风险表现差异大 | 中 | 分层建模 / 引入产品类型、新老客户变量 |
| 多源数据不一致 | 中 | 抽样核查 + 结合业务判断以哪张表为准 + 缺失值按业务含义灵活分箱 |
| 工程落地周期长 | 中 | 预留部署/验证/培训时间；模型上线不止算法，还涉决策引擎、变量加工、接口、测试、培训 |
| 可解释性监管要求 | 中 | 逻辑回归 + WOE + 业务校验（可解释优先），谨慎使用黑盒模型 |

---

## 12. 关键成功要素（KSF）

1. **坏样本处理方法论**是建模成败关键——小微低逾期场景下的定义调整 + 过采样 + 验证策略组合
2. **字段映射表 + 历史回放 + PSI 监控**三件套根治特征线上线下不一致（本项目最大工程坑）
3. **可解释性优先**（逻辑回归 + WOE + 业务校验）是银行风控落地的前提
4. **集成商定位**（不替换决策引擎、用低代码平台管模型全生命周期）保护客户既有投资
5. **资产化沉淀**：策略资产/字段映射表/SOW 模板/验收 Checklist → 可复制到同类农商行
6. **LTV 扩展复用同一套低代码平台**——贷后预警（风险）与 LTV（价值）共享数据集市、特征工程、部署架构、监控体系
