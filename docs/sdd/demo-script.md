# 3 分钟演示脚本

> 演示路径：角色切换 → 预警探照灯 → 核查工作台 → 企查查 Agent 评估
> 目标：展示"角色化工作台 + AI 辅助风控"的核心价值

---

## 开场（15s）

> "这是一个面向银行客户经理的贷后风控工作台。核心理念是：**一个平台完成预警发现→核查处置→策略实验的全链路，AI 辅助风险评估，人工只做高价值决策。**"

**操作**：打开首页，当前默认角色为**客户经理（RM）**。

---

## 第一站：角色化首页（30s）

> "平台支持三种角色，首页内容完全差异化。"

**操作**：
1. 指向 RM 首页的 4 个 KPI 卡片 — "客户经理一打开就看到今天有多少预警要处理、哪些快超时了"
2. 指向任务列表 — "按紧急度排序，高风险预警置顶"
3. **点击顶部角色切换器**，切换到「风控建模师」 — 首页变为模型实验状态
4. 再切换到「策略审批员」 — 首页变为待审批列表
5. 切回「客户经理」

> "三种角色看同一套系统，但每个人打开首页看到的都是跟自己最相关的内容。侧栏菜单也会联动变化。"

---

## 第二站：预警探照灯（40s）

> "现在看客户经理最核心的场景：预警发现。"

**操作**：
1. 点击侧栏「预警探照灯」进入 `/monitor/dashboard`
2. 指向预警列表 — "这里有级别、企业、类型、触发时间"
3. 指向一条 CRITICAL 级别的预警 — "红色标签表示高风险"
4. 点击该预警进入核查工作台

---

## 第三站：核查工作台（50s）

> "这是处置闭环的核心页面。左侧预警列表，右侧详情面板。"

**操作**：
1. 右侧面板展示风险画像 — "9 个维度的风险评估，每个维度有具体证据"
2. 指向处置建议 — "系统会根据风险类型给出处置建议和 SLA 要求"
3. 点击「认领」按钮 — 状态从「待认领」变为「核查中」
4. 指向关联信息 — "这里能看到关联的欺诈模式（FP）和调优案例（RC）"
5. 点击「提交核查结果」 — 状态变为「核查完成」

> "整个流程在一个界面完成，不用切换系统。状态流转有完整记录。"

---

## 第四站：企查查 Agent 风险评估（40s）

> "平台集成了企查查 MCP，支持 65 个数据工具的企业风险评估。"

**操作**：
1. 点击侧栏「企业风险评估」进入 `/agents/vendor-risk-assessment`
2. 输入企业名称（如"蚂蚁集团"），点击「开始评估」
3. 等待评估结果 — "3 秒内返回"
4. 指向评估报告：
   - "整体风险等级"
   - "9 个维度的详细评分"
   - "18 类风险清单，每条有证据链"
   - "处置建议，包含动作、SLA、责任人"

> "这个 Agent 是独立的底层能力，预警归因和处置建议都可以调用它。MCP 不可用时会自动降级。"

---

## 收尾（15s）

> "总结一下：角色化首页让每个人看到最相关的信息；预警→核查→处置的闭环在一个工作台完成；企查查 Agent 提供 AI 辅助的风险评估。后端离线时，MSW Mock 层可以支撑完整演示。"

## 常见面试问题预备

| 问题 | 回答要点 |
|------|---------|
| 状态管理为什么选 Zustand？ | 3 个 store 平均 < 100 行，无 boilerplate；项目状态扁平，不需要 Redux DevTools |
| Mock 层怎么设计的？ | MSW 浏览器端拦截，`VITE_USE_MOCKS` 一键切换；mock 与真实 API 共享同一套 TypeScript 类型 |
| 角色系统怎么实现的？ | Zustand + persist localStorage；角色切换驱动首页/侧栏/导航三处联动 |
| Agent 怎么集成的？ | 企查查 MCP 65 tools 封装在后端；前端通过 REST API 调用；独立路由，可被其他 Agent 调用 |
| 这个项目最大的技术债？ | 处置闭环的状态机还是二态（active/resolved），spec 设计了五态枚举；催收/质检模块 UI 骨架在但数据硬编码 |
